Turning Three Smart-Meter Silos into Automated Billing and Analytics

A high-volume Oracle Utilities MDM implementation connecting three vendor head-end systems to SAP-ISU and turning meter data into billing, theft detection and network-health insight.

The Problem

  • Meter readings were manually accumulated and fed into SAP billing, creating a slow, labour-intensive process with limited real-time visibility.
  • Smart meters from three vendors reported into three separate Head End Systems, creating disconnected data silos despite producing valuable interval, network and event data.
  • The utility could not automatically feed validated usage into billing, identify unauthorised/excessive consumption at service-point level, or use event data for proactive meter and network maintenance.

The Solution

  • iTANZ integrated Oracle Utilities MDM with all three vendor HES platforms and connected MDM to SAP-ISU for automated consumption flow from meter through to billing.
  • Designed high-volume ingestion for 5–7GB of daily data using archive logging, continuous replication, Change Data Capture and appropriate slowly-changing-dimension patterns.
  • Transformed normalised source data into star and snowflake analytical structures, facts, dimensions and materialised views through data-integration tooling.
  • Enabled analytics for theft/unauthorised usage and network/meter health from interval and event data.
  • Later migrated the MDM platform from legacy Exadata/Exalogic to modern Exadata and Private Cloud Appliance and continues to support the landscape.
Technologies Used

Oracle Utilities Meter Data Management (MDM) • Oracle Utilities Application Framework (OUAF) • SAP-ISU • Three vendor Head End Systems (HES) • Database replication and Change Data Capture (CDC) • ETL / analytical data integration • Oracle Exadata • Oracle Private Cloud Appliance

Impact We Created

Automated meter-to-bill flow

Automated consumption-data flow from three HES environments into SAP billing without manual meter-reading capture in the chain.

Scale held at 5–7GB a day

Established processing for 5–7GB of daily meter data while maintaining a usable analytics structure.

Theft and network insight

Enabled service-point-level theft and unauthorised-consumption analysis plus meter and network health insight.

An operating relationship

Extended the engagement into infrastructure modernisation and ongoing support, making the reference an active operating relationship rather than a one-time implementation.

The Conclusion

The K-Electric case demonstrates iTANZ’s ability to make multi-vendor smart-meter data operational at scale—connecting it to billing, analytics and long-term platform operations through Oracle Utilities MDM.
